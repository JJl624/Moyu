# 编辑器输入与文档约定

本文件约束所有平台共用的编辑器，当前验证目标为 Windows 和 Android Gecko。界面组件负责表达操作意图；文档层负责结构和内容；原生输入层负责输入法状态。修改这些路径时同时更新规则测试。

## 光标和输入归属

- 空的 `tabs` 围栏在编辑器中先显示代码源码；已有标签内容的围栏仍显示标签页。`codeTabs.ts` 的编辑结果同时返回实际源码与新的正文偏移，新增分隔换行必须计入选区映射；不得继续使用编辑前的 EOF 声明偏移，否则第一次输入的光标会落在文字之前。
- ProseMirror 保存整篇文档的逻辑选区，CodeMirror 保存当前代码页内的选区；标签页通过源码偏移转换，不能把页内位置当作文档位置。
- `selectionOwnership.ts` 是共享富文本命令获取输入焦点的入口。调用者先提交文档与逻辑选区，再通过该入口交接输入；不能在各插件中直接调用外层 `view.focus()`。
- 完整源码编辑器通过 `sourceSelectionOwnership.ts` 使用同一权限策略。焦点调用必须明确给出操作意图，没有默认的“允许编辑”权限。
- `codeSelection.ts` 管理代码输入面注册。普通代码、标签代码和公式块都使用相同的焦点规则；销毁时必须注销。未完成挂载的请求只能等待当前输入面，不能作用于已销毁的视图。
- 代码输入面延迟挂载时，重新检查当前逻辑选区、输入权限和输入归属，不能重放旧光标偏移；缺少代码输入面时禁止退回正文抢焦点。
- `scripts/stable-code-blocks.ts` 在 Milkdown 7.22.2 的构建副本中保持代码块的文档生命周期，并抑制相同代码选区的重复焦点与事务。未打开的内置语言菜单不计算位置，打开后仍正常定位；开发预打包和发布构建共用同一转换，升级必须通过锚点及行为测试，不修改 `node_modules`。
- 同步选区不代表允许弹出键盘。`selectionPolicy.ts` 区分 `edit`（明确开始编辑）、`node-update`（模型同步）、`history`（撤销重做）、`restore`（恢复）。后两者在手机键盘关闭时不得抢焦点；模型同步只有键盘导航或删除交接才允许获取焦点。
- 只读或正在输入法组字时，不执行程序化焦点交接。DOM 选区只从正文可编辑区读取，不能从代码编辑器、预览或拖选结果推断正文光标。
- 逻辑光标与原生折叠选区已经相同则不重复 `collapse()`；实际位置不同或选区未折叠仍须通过同一归属入口校正，不能以性能优化跳过必要的光标交接。

## 代码边界

- `codeBoundary.ts` 统一定义边界：当前文档中的折叠文本选区、段落首尾、同容器的直接代码兄弟节点。跨层级、非空选区、过期文档均不属于边界。
- `blockNavigation.ts` 负责跨边界的文档事务。空外部段落允许删除时才删除；列表项必需的首段落保留；随后把逻辑光标交给代码输入面。
- 用户在代码内部删除与从块外跨边界是两种操作。前者允许正常删除空块；不能通过通用的空块清理规则替代后者。
- `codeBoundaryIme.ts` 仅适配 Gecko 的原生删除事件，状态为闲置、指针选择、已记录边界、已销毁。它不另建文档操作规则。原生过渡选区必须属于同一不可变文档快照；新触摸、其他输入、文档更换和销毁使其失效。

## 结构操作与可视位置

- 入列表、脱离列表是结构修改，不是光标导航，不请求 `scrollIntoView()`。
- 文档返回及模式切换由 `viewSelection.ts` 在初始化时限内等候媒体/代码布局稳定后显示正文。加载图片引起的浏览器滚动锚定不代表用户导航，不能仅因 `scroll` 事件提前终止恢复；明确输入、较新的恢复请求和编辑器销毁释放本次恢复。
- 自动揭示选区时，代码块以内层 CodeMirror 光标为准；实际光标已可见就不滚动，不能用块外框代替光标判断，撤销重做也遵守此规则。
- `structuralViewport.ts` 在事务开始前保护当前可视范围，防止代码视图和列表 DOM 暂时移除时滚动条被浏览器夹回。只保留当前可视范围所需的最低高度，不保留整篇历史最大高度。
- 事务后同步恢复滚动位置，并在代码控件挂载的微任务结束后再核对一帧；文档已改变、新触摸或键盘操作取消这次核对。禁止定时反复恢复，不能抢用户后续滚动或输入。
- 下一次实际输入、组字或滚动手势释放临时高度；历史操作不当作新输入。编辑器销毁必须清理监听和样式。此过程不修改文档、保存状态或键盘可见性。

## Markdown 解析顺序

编辑、阅读、源码位置映射共用 `shared/remark-document-structure.mjs`，顺序固定为：

1. `remark-legacy-empty-code.mjs`：兼容旧版产生的异常空代码围栏。
2. `remark-empty-paragraphs.mjs`：只处理明确的空段落标记。
3. `remark-empty-tasks.mjs`：保留没有可见文字的任务项及其勾选状态。
4. `remark-lists.mjs`：统一相邻列表边界和编号。
5. 各界面的行内语法与显示转换。

旧格式兼容必须先于行内源码转换，否则转义后的标记会被包装成普通行内内容。兼容转换只修改解析结果，打开文档不写磁盘；不能扩大为通用 HTML 或任意围栏的自动修复。

空段落标记由 `shared/empty-paragraph.mjs` 定义。列表和引用里的空段落需要保留；根级空段落主要用于放置光标，两个独立同类列表之间的空段落仍须阻止列表合并。序列化的空标记后必须保留必要空行，不能让 HTML 吸收后续代码围栏。

## 文档发布和保存

- 公式辅助输入使用独立 MathLive 草稿，阅读渲染仍使用 KaTeX。`formulaEditing.ts` 与 `sourceFormulaEditing.ts` 分别持有富文本/源码的不可变快照；确认时验证文档、输入权限和存活状态，再以一次可撤销事务写回 LaTeX。取消、符号键盘和草稿输入不改正文。源码公式保留引用/列表前缀和原有换行格式；普通代码与行内代码不作为公式处理。焦点仍通过现有输入归属入口恢复。
- 公式输入默认只显示可视输入面，LaTeX 源码按需展开，符号键盘使用 MathLive 内置入口，不重复放置按钮或公式类型说明。弹窗和键盘应适应小窗口；Ctrl+Enter 与“应用”使用同一草稿提交入口，组字期间不提交。
- `formulaControls.ts` 适配公式块的原生操作组，辅助输入按钮使用普通流布局，不能用固定右侧偏移覆盖原生按钮。随代码视图的懒挂载/卸载重新接入操作组；观察仅限块宿主的直接子节点，不因代码输入反复扫描，销毁时断开监听。

- 附件预览按 `docs/attachment-previews.md` 的类型与段落规则接入。第三方渲染器不拥有正文选区，不能修改结构、请求正文焦点或触发正文保存。新增类型先复用既有引用编辑与拖选规则，不另建边界删除逻辑。

- `DocumentSession` 为每篇已挂载文档持有源码基线、最新读出结果和已发布文档，切换文档重新创建。
- `read()` 只读取当前 Markdown，可以缓存结果，不能确认已发布、写文件或清除未保存状态。
- `publish()` 将当前不可变文档转换后交给上层。只有通知成功才更新已发布状态；读取、转换异常、通知失败均不能消耗待发布编辑。
- 保存基线只在上层的 `savedValue` 实际推进后改变，不能因为读出、切换视图、生成代码 ID 或撤销而推进。保存完成后仍有新输入时，新输入继续保持待保存状态。
- `MarkdownSource` 保留未修改区域的原始 Markdown。局部拼接必须重解析验证；完整回退序列化还须通过 `documentContract.ts` 的持久块结构检查，失败时停止发布和保存并保留编辑内容。
- 持久结构包括块类型与顺序、列表层级和起始编号、任务勾选状态、代码语言/元数据/原文。生成的列表标签、标题 DOM ID、松紧列表排版不作为持久结构。行内文本与格式由原有行内编码器和相应回归验证，块检查不代替行内格式测试。
- 磁盘写入、自动保存、历史和同步属于上层文档管理，不能由选区或节点视图触发。

## 验证入口

- `tests/editor-contracts.test.cjs`：焦点权限、边界有效期、读取/发布/保存基线及有损转换阻止。
- `tests/list-mutations.test.cjs`、`tests/selection.test.cjs`：结构、源码位置和往返规则。
- `npm run test:mobile`：全部移动浏览器回归，每个用例统一拦截未捕获应用错误。浏览器模拟结果不等同于原生输入法验证。
- `tests/mobile-device-empty-code-boundary.mjs` 等原生脚本：在独立调试应用中验证真实软键盘、光标和文件保存。测试记录注明设备与输入法；Gboard 模拟器不能代表小米与百度输入法。

新增规则应放入上述共享模块并增加正反用例，避免在界面组件中增加同一规则的另一套判断。第三方编辑器自身的内部焦点操作由适配器隔离，不直接修改依赖包。
