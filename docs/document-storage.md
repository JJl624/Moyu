# 文档附属存储

## 唯一来源

- 正文仍为普通 Markdown；附件、代码数据与钉住的 HTML 文件仍独立存储、独立同步，不打包进容器。
- 有附属目录的文档由 `<文档名>.assets/document.json` 保存归属、编号上限、已保存块 ID，以及 `results[块 ID].items` 钉住记录、`attachmentViews[引用路径]` 附件视图偏好。维持记录版本 2，以附加字段扩展。
- `.data/document_map.json` 版本 3 对已关联文档仅保存目录位置，可以由 `document.json` 重建。不能用索引中的旧编号覆盖附属记录。
- 尚未产生附属内容的代码文档，其编号预留暂存在总记录中，作为该文档编号的唯一来源；第一次使用附属内容时转交给 `document.json`。这部分不是可丢弃缓存，避免为纯代码笔记创建空附属目录。纯文本笔记不新增记录。
- 已关联文档的记录损坏或缺失时停止分配编号和写附属内容，禁止从默认值 1 静默重建。

## 创建、迁移和读取

- 只创建实际使用的 `attachments/`、`code-data/` 或 `results/`。旧索引迁移时只用非递归 `rmdir` 移除确认归属目录内的空管理子目录，不删除未知目录、链接或非空目录。
- 旧索引的编号上限在迁移时取较大值，先写权威记录，再提交精简索引；后续普通内容修改不会反复改写位置索引。
- 旧 `results/<ID>/results.json` 继续可读。在实际钉住、取消或改变高度时合并进文档记录；记录成功落盘后才清理内容未变化的旧 JSON。HTML 文件不搬动。阅读和相同高度操作不触发迁移或写入。
- 文档记录中存在某个结果 ID（包括空 `items`）就优先于旧 JSON，避免清理中断或旧文件再次下载后恢复已取消的结果。安卓读写同一格式并保留其他字段。
- 附件视图只读恢复不创建记录；实际改变选项时才合并写入现有文档记录，首次只创建 `document.json`。不改正文、不记正文历史，记录正常同步；同步下载命中文档记录时刷新当前已加载视图。按文档和引用路径隔离，复制/重命名时重写相对路径键。
- PDF 的翻页命令通过公开命令状态立即记录目标页，普通滚动记录当前页；不能用双页布局的临时首个可见页覆盖用户选择的页，也不能因忽略布局事件而提前推进已记录页码。关闭、切换及同步复用既有视图排空入口，不依赖 DOM 销毁后的事件；未操作的阅读器不产生写入。
- 编号更新、复制、重命名、关联和回滚必须保留钉住信息。不能在通用记录写入时丢弃 `results`、`attachmentViews` 或其中未来版本的未知视图字段。
- 提交记录前核对读取快照；外部修改与缓存状态冲突时停止覆盖。先提交集中记录，再清理仍与读取快照一致的旧结果 JSON；无法完整识别的旧记录保留。
- JSON 读取共享知识库级缓存，以文件身份、大小与纳秒修改时间/变更时间判断失效；外部修改和下载后重新读取。文件列表只需位置索引，不读每篇文档的管理记录。归属发现不进入已识别的附属目录扫描用户附件和代码依赖。

## 本机状态

桌面历史继续存放知识库统一的 `.data/history.sqlite`；同步基线、索引、历史和恢复事务留在 `.data`。安卓历史沿用应用私有存储。缩略图和临时运行结果沿用内存或应用缓存，不新增文档附属文件。同步只传正文、附件、代码数据、文档记录和明确钉住的结果；`.data` 不上传。
